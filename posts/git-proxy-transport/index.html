浏览器能访问，Git 克隆却失败？先看仓库地址类型

小六2026-10-08— 次阅读
客户端教程

GitHub 网页能打开，git clone 却失败，常见原因之一是浏览器和 Git 没有走同一条连接。先把仓库地址看清楚，再查设置。

HTTPS 和 SSH，查的不是同一处

以 https:// 开头的地址，与常见的 git@... 地址，可能使用不同传输方式。Git 的 http.proxy 不是给所有方式统一加代理的开关，SSH 需要按它自己的连接方式检查。

有时本地还配置了地址重写，表面复制的是一种地址，实际使用的可能是另一种。

先查看，不急着永久改配置

已有仓库中，可以用下面的命令查看远程地址：

git remote -v

分享输出前，隐藏私人仓库路径和可能嵌在地址中的凭据。还没克隆时，就先核对准备使用的完整地址。

再检查 Git 版本、使用的程序位置和代理配置来源。系统、个人和项目目录中的设置可能不同，编辑器内置 Git 也未必与终端是同一环境。

按错误类型继续查

连接本地代理失败，先看客户端端口；连接目标超时，检查网络路径；证书报错，核对时间与信任设置；账号或密钥报错，则要检查访问权限。

不要把所有错误都归为网速慢，也不要用关闭证书验证来掩盖问题。

网页能看，不代表仓库能下载

仓库权限、文件下载和不同传输方式各有条件。固定一个仓库地址和一套环境，做一次明确的代理对照，比反复切换全局设置更容易找到原因。

求助时提供地址类型和脱敏的错误末尾，通常已经足够开始判断，不需要公开访问令牌。

Windows 代理正常，WSL2 却连不上？先看 localhost 指向谁

小六2026-10-11— 次阅读
客户端教程

Windows 浏览器能用代理，WSL2 里的命令却超时，常见误区是把 Windows 的 127.0.0.1 原样填进 Linux，就以为一定能连到同一个地方。

先确认 WSL 的网络模式

WSL2 的常见网络模式，对本机地址的处理不同。在默认 NAT 场景下，从 Linux 访问 Windows 服务通常要找到 Windows 宿主机的相应地址；支持的镜像模式则有不同的 localhost 互通方式。

别只看“WSL2”三个字就套教程。Windows 版本、WSL 版本和当前模式，都需要一起核对。

Windows 能用的端口，也要允许 WSL 访问

先确认客户端的实际代理类型与端口。如果入口只接受 Windows 本机连接，WSL 从另一地址访问时可能失败。

按当前模式的微软文档与客户端说明设置必要范围。不要为了测试关闭整个防火墙，也不要把只需本机使用的代理暴露给无关网络。

Linux 里的工具也要有自己的代理设置

curl、Git 和其他工具不一定自动使用 Windows 浏览器的配置。可以先给一次测试请求明确指定代理，确认地址和端口可用，再决定是否配置环境变量。

若使用自动代理功能，还要确认当前 Windows、WSL 版本满足要求，以及使用的工具能否读取相关设置。

按四项记录，问题更容易说清楚

记录 Windows 和 WSL 版本、网络模式、代理入口，以及错误发生在连接入口、查询域名还是访问目标时。真实凭据不要放进输出。

先让一次明确的请求成功，再调整长期设置。网上某个固定虚拟网卡 IP，不能代替你当前环境里的实际地址。
